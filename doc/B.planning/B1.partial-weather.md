## Issues & caveats

1. **B1 gap:** Weather endpoints are not in the B1 Local API Targets table; implemented per workstream assignment and noise-app context (wind/temp for open-window exposure).
2. **Open-Meteo grid snapping:** Upstream rounds coordinates (e.g. Kings Cross `51.5308,-0.1238` → grid `51.5, 0.0` in forecast). Acceptable for city-scale weather; note in merge confidence.
3. **OpenWeather blocked:** No `OPENWEATHER_API_KEY` in env. Open-Meteo is sufficient as keyless primary; OpenWeather is optional redundancy.
4. **Climate API latency:** Climate normals request ~1–3 s (large decadal daily series). Cache if used in production scoring.
5. **Not noise core:** Weather is P2 enrichment — explains seasonal open-window behaviour, not transport/nightlife noise directly.
